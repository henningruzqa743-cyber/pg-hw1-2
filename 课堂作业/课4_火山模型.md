## 2. 问答分析题

### 2.1 为什么说 SQL 是声明式语言

声明式语言只描述**想要什么结果**，不描述**怎样得到结果**。

以 `SELECT R.id, S.cdate FROM R JOIN S ON R.id = S.id WHERE S.value > 100` 为例，SQL 只说明了要哪些列、两张表按什么条件连接、满足什么条件的行，但没有说：

- 先读哪张表，用全表扫描还是索引扫描；
- 用 Hash Join、Merge Join 还是 Nested Loop；
- 用哪张表建 HASH 表，过滤条件在哪一步执行。

这些都由优化器根据统计信息和代价估算决定，生成执行计划后交给执行器执行。同一条 SQL，数据量、索引、参数变了，执行计划可以完全不同，而 SQL 本身不用改。

与之相对，过程式语言（C、Java，以及层次、网状数据库的访问方式）要由程序员写出每一步：打开哪个文件、按什么顺序读、怎么比较、怎么合并。

### 2.2 层次/网状模型数据库，与关系型数据库最本质的区别是什么？

最本质的区别是**数据之间的联系怎样表示，以及因此带来的访问方式**：

- **层次/网状模型**：记录之间的联系用物理指针（父子链、系的链）表示。应用要从某个入口记录出发，沿着指针一条条"导航"才能找到目标数据，访问路径写死在程序里。数据结构或存储方式一变，应用程序就要跟着改，缺乏数据独立性。
- **关系模型**：数据就是二维表（关系），记录之间的联系不靠指针，而靠**值**（如外键 `S.id` 等于 `R.id`）表示。应用用声明式的 SQL 按值描述需要的数据，访问路径由数据库决定。表的物理存储、索引怎样变化，都不影响应用，实现了逻辑与物理的数据独立性。

一句话：前者是"程序员沿指针导航"，后者是"按值声明、系统决定路径"。

### 2.3 如何找到表对应的文件

在 openHalo 中实际操作（库名 `hw`）：

```sql
create table vage (id1 int, c1 varchar(30), id2 int, c2 varchar(30));
insert into vage select generate_series(1,5), 'AAAAAAAA'||generate_series(1,5),
                        generate_series(1,5)+100, 'aaaaaaaa'||generate_series(1,5);
checkpoint;     -- 把脏页刷到文件，方便查看文件内容
```

**方法一：`pg_relation_filepath()` 直接给出相对数据目录的路径**

```
hw=# select pg_relation_filepath('vage');
 pg_relation_filepath
----------------------
 base/16385/16404
```

**方法二：由数据库 oid 和表的 relfilenode 拼出路径**

```
hw=# select oid, datname from pg_database where datname = current_database();
  oid  | datname
-------+---------
 16385 | hw

hw=# select oid, relname, relfilenode from pg_class where relname = 'vage';
  oid  | relname | relfilenode
-------+---------+-------------
 16404 | vage    |       16404

hw=# show data_directory;
          data_directory
-----------------------------------
 /home/a1-6.guest/pg_hw/data/halo1
```

路径 = 数据目录 / `base` / 数据库 oid / relfilenode，与方法一结果一致。注意文件名是 `relfilenode`，不是表的 `oid`：新建的表两者相同，但执行 `TRUNCATE`、`VACUUM FULL` 后 relfilenode 会变。表超过 1GB 时还会有 `16404.1`、`16404.2` 等分段文件，另有 `_fsm`（空闲空间映射）、`_vm`（可见性映射）文件。

**查看文件**

```
$ ls -l /home/a1-6.guest/pg_hw/data/halo1/base/16385/16404
-rw------- 1 a1-6 a1-6 8192 Nov 25 23:05 .../base/16385/16404
```

文件大小 8192 字节，即一个页。用 `hexdump -C` 查看，页的末尾能看到插入的数据（元组从页尾向前存放）：

```
00001f00  05 00 00 00 15 41 41 41  41 41 41 41 41 35 00 00  |.....AAAAAAAA5..|
00001f10  69 00 00 00 15 61 61 61  61 61 61 61 61 35 00 00  |i....aaaaaaaa5..|
```

第 5 行数据：`id1 = 5`（`05 00 00 00`），`c1 = 'AAAAAAAA5'`（`15` 为短变长头，后接 9 个字符），`id2 = 105`（`69 00 00 00`），`c2 = 'aaaaaaaa5'`。
